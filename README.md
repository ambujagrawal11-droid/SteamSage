# SteamSage — ExaThon India 2026

**SteamSage is a prototype for industrial steam-trap fault triage and maintenance prioritization.** It uses Exasol Personal as the analytics database, Python for transparent diagnostic rules and cost estimates, and Streamlit for the dashboard.

> **Important:** This is a hackathon prototype using synthetic data. It is not validated for live plant decisions. The readings, labels, loss rates, and steam prices are simulated. A real deployment would require calibrated inspection methods, plant-specific engineering models, and validation by qualified personnel.

## What it demonstrates
- Synthetic steam-trap dataset with 500 illustrative records.
- Exasol Personal connection via `pyexasol`.
- Load the sample CSV into an Exasol table from the app.
- SQL-based triage categories: suspected leak, suspected blockage, needs inspection, and no immediate flag.
- Transparent potential-cost estimate and ranked inspection queue.
- Streamlit dashboard and exportable results.

## Quick start
1. Install Python 3.10–3.12.
2. Create and activate a virtual environment.
3. Install dependencies: `pip install -r requirements.txt`
4. Copy `.env.example` to `.env` and fill in the connection values from your Exasol Personal instance.
5. Run `streamlit run app/streamlit_app.py`.
6. In the sidebar, choose **Exasol Personal** mode, connect, and click **Load/refresh synthetic sample in Exasol**.
7. Review the dashboard and export the diagnosis table.

For a quick UI preview without database credentials, select **Demo mode (local synthetic data)**. Demo mode is for preview only; use Exasol mode for the competition demonstration.

## Exasol connection
Set these in `.env`:
- `EXASOL_DSN`: host/port or DSN provided by your Exasol Personal setup.
- `EXASOL_USER`: database username.
- `EXASOL_PASSWORD`: database password.
- `EXASOL_SCHEMA`: optional schema name; defaults to `STEAMSAGE`.

The app creates the schema if supported by your permissions and creates/replaces `STEAMSAGE_TRAPS`. If your Exasol Personal setup uses a pre-created schema or restricts schema creation, create/select a schema you own and set `EXASOL_SCHEMA` accordingly.

## Data dictionary
| Column | Meaning |
|---|---|
| `trap_id` | Synthetic asset identifier |
| `trap_type` | Simulated trap type |
| `steam_pressure_bar` | Simulated operating pressure |
| `temperature_c` | Simulated measured temperature |
| `ultrasonic_index` | Simulated relative ultrasonic signal index; not a calibrated unit |
| `operating_hours_per_day` | Simulated daily operation |
| `inspection_age_days` | Days since last inspection |
| `estimated_loss_kg_hr` | Simulated loss assumption, not a measured loss |
| `steam_cost_inr_per_tonne` | Illustrative price assumption |
| `synthetic_reference_label` | Synthetic label used only for demo evaluation; not used by the diagnostic SQL |

## Method
The SQL rules are intentionally interpretable and are demonstration thresholds, not universal engineering thresholds:
- High ultrasonic index plus elevated temperature → suspected leak.
- Low temperature plus low/moderate ultrasonic index → suspected blockage.
- Other elevated signals or old inspection → inspect/uncertain.
- Otherwise → no immediate flag.

Potential annual cost is calculated as `estimated_loss_kg_hr / 1000 × steam_cost_inr_per_tonne × operating_hours_per_day × 365`. This is a scenario estimate, not a measured saving or guaranteed avoidable cost. Treat estimates as directional until verified.

## Security and reproducibility
- Never commit `.env` or credentials.
- The supplied data is synthetic and generated by `scripts/generate_data.py` (the bundled CSV is included for convenience).
- To regenerate: `python scripts/generate_data.py`
- Pin or record dependency versions before final submission.
- Verify the current event portal for the exact submission form and deadline.

## Disclaimer
SteamSage is decision support, not an autonomous safety system. All flagged traps require qualified verification before maintenance action. Do not use the prototype as the sole basis for process or safety decisions.
